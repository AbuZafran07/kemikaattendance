# Integration architecture
- External backups export the existing ten-table JSON format fail-closed, verify private destination readback, and retain only owned-prefix files; managed cron and server-verified administrators share one handler without altering internal schedules.
- Render unlock-letter previews from existing signed records with the current PDF generator; this fixes old layouts without rewriting signatures or approval history.
- Bulk late-reason approval reuses the existing per-request decision RPC and retains only failed selections; this preserves server validation, audits and notifications without a second approval path.
- Recheck rejected leave/travel dates in database triggers, skipping attendance, protected requests and non-working dates; decisions must not depend on the daily worker revisiting history.
- Enforce employee attendance timestamps and timing-derived status in database triggers; administrative historical corrections retain their existing path and the UI reads saved results.
- Serialize missing-reason scans and submissions on attendance rows using the shared configured deadline; skip any attendance with prior violation history regardless of counted status and retain the counted per-date guard so HR waivers cannot be undone by rescanning. Server-derived windows govern history controls, and only timely submissions protect counts.
- Reuse superseded monthly SP rows with atomic conflict handling and fresh documents; HR waivers require notes and reconcile discipline through immutable audits.
- Permit admin/HR historical corrections and locked employees' checkout; reconcile invalid warnings and automatic locks with immutable audit history when late counts are corrected.
- Enforce pending/approved late-reason protection in database triggers as well as the scheduled checker, so stale workers cannot count HR delays as employee violations.
- Author remote agent tools in `src/lib/mcp`, with one SDK tool per file and SDK-generated transport; this keeps the published catalog aligned with handlers.
- MCP database access must use the verified OAuth caller's shared lazy client and existing RLS; no privileged or anonymous fallback is permitted.
- Browser tools register in their owning screen using `useWebMCP` and the shared telemetry helper; this bounds their lifetime and preserves normal UI operation.
- Preserve canonical same-origin consent return paths through existing password login; employee registration remains administrator-managed.
- Generate counted-violation notices and threshold actions atomically in the attendance insert trigger, merge existing employee warning messages by event key, and link dated notifications to WIB-bounded history; this prevents duplicate notices and incorrect next-day rejection dates.
- Run the SQL-only reason reminder hourly with attendance-row locking and unique event keys; daily checks cannot reliably cover the four-hour reminder window.
- Count employee attendance notices after the server last-seen timestamp and use unique scoped realtime channels; shared channel names leak subscriptions when multiple badge hooks mount.
- Deliver employee attendance push exclusively from a server queue with atomic leased claims, age/attempt eligibility and success-only pushed_at; compare the failed device token before clearing it so replacement registrations survive. Use connector-backed FCM v1, with service-account OAuth exchange managed by the connector.
- Initialize the messaging worker independently of open tabs, let Firebase display notification payloads, and intercept clicks before its handler with same-origin navigation; this prevents duplicate displays and preserves dated destinations.
